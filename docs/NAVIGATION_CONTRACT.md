# Navigation Contract v1

## Ziel

Ein Nutzer muss Wissen finden können, ohne dessen Speicherort oder technischen Namen zu kennen.

## Primäre Einstiege

1. Heute wichtig
2. Entdecken
3. Suchen
4. Problem lösen
5. Projekt verbessern
6. Lernen

## Regeln

- maximal vier sichtbare Hierarchieebenen
- danach Facetten, Beziehungen und Suche
- stabile Grundstruktur; adaptive Sortierung priorisiert Inhalte, verändert aber nicht täglich die Navigation
- kein Zustand ausschließlich über Farbe
- Anfängeransicht zeigt zuerst: Was ist das? Warum wichtig? Was soll ich tun?
- Technikdetails werden progressiv eingeblendet

## Pflicht-Facetten

- Typ
- Hauptkategorie
- weitere Kategorien
- Tags
- Projekt
- Priorität
- Reife
- Status
- Gültigkeitsbereich
- Automatisierbarkeit

## Abnahmeszenario

Der Eintrag `RULE-001` muss ohne Datenkopie mindestens über Typ Regel, Kategorie Tests, Nebenkategorie Release, Priorität P0, Tag PASS, Projektbezug und Volltextsuche auffindbar sein.
